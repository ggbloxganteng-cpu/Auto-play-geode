# v0.7.0 integration notes

## Integrated in this source tree

- `src/core/performance/AdaptiveScheduler.hpp` is connected to the PlayLayer update path.
- The real player's `incrementJumps()` edge starts the configured jump grace window.
- Floating panel controls cycle Ultra Low / Low / Balanced / High and toggle Adaptive Budget.
- Panel telemetry reports preset, current extra-work budget, average frame time and jump-grace status.
- Preview simulation is throttled and deferred during jump grace / detected frame hitches.
- When Auto Play is off, predictive work is skipped on frames where the preview is not due.
- Auto Play's live decision path is deliberately not paused by jump grace.
- Deep Wave search is limited to High/Custom and is deferred during jump grace.
- Simulation lookahead is capped per preset: 72 / 120 / 200 / 320 physics substeps.
- Performance diagnostics can emit periodic scheduler telemetry to the Geode log.

## Included but not yet connected to live game objects

- `IncrementalWork.hpp` and `StaticFingerprintCache.hpp` are portable helpers with unit tests. The level scanner still performs a synchronous scan at level initialization.
- The current four-zone scan is still descriptive telemetry, not an isolated future-world simulation.
- A complete global route planner and persistent checkpoint simulation remain future work.

## Verification status

- `sh tests/run.sh`: passed, including the new scheduler/performance tests.
- `mod.json`: valid JSON.
- Full Geode Android compilation and in-game profiling: not run in this environment. Run the included GitHub Actions workflow or build with the matching Geode SDK before installing.

## Suggested first device test

Start with **Ultra Low**, Auto Play off, and trajectory on. Check panel responsiveness and frame pacing while moving through a dense section. Then enable Auto Play separately and compare. If the mod crashes or input timing changes, disable it and capture the Geode log; do not raise the preset until the baseline is stable.
