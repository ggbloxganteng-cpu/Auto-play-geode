# v0.7.0-B / C / D implementation notes

## B — Segment simulation + checkpoint

Added `src/core/planning/SegmentPlanner.hpp`:
- Computes a bounded segment window from the current X position to a checkpoint boundary.
- Uses measured horizontal distance per physics substep supplied by the caller; it deliberately does not guess player speed.
- Provides a segment score that combines survival ratio and object-class density.

Current status: the primitive and offline tests are implemented. Live `runSimulation()` still runs a continuous horizon; checkpoint-bounded clone execution and carry-over of clone state between segments remain to be wired. The current four-zone level scan remains metadata only.

## C — Global route planner

Added `src/core/planning/GlobalRoutePlanner.hpp`:
- Bounded beam search across four checkpoint segments.
- Each segment has two measured control outcomes (release / hold).
- Minimizes cumulative simulated risk plus a small input-switch penalty.
- Beam width is clamped to 1–16.

Current status: algorithm and synthetic regression test are implemented. It is not yet fed by live segment simulations and does not currently change Auto Play input. Do not interpret its offline output as a validated route through a live level.

## D — Wave Planner 2.0

Integrated into `Simulation.hpp`:
- Replaces the fixed four/six candidate list with deterministic frame-aligned candidate generation.
- Tests both straight paths first and stops early if either survives the horizon.
- If both fail, expands one-switch corrections; deep mode adds two-switch sequences.
- Hard candidate caps: 6 light / 12 deep, max 2 switches per candidate.
- Existing live transition scheduler still executes only the first planned switch and revalidates the current path before switching.

`sh tests/run.sh` passes, including the new `planning modules: ok` test. These are offline portable logic tests, not Geometry Dash physics validation. No Geode Android build or device FPS test has been run in this environment.
